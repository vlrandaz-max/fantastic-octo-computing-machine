## How to change it (the next time a space leases or opens)

1. Edit `tools/build_site.py`.
   - **Hub cards:** the `SPACES` list. Delete a dict to take a space off, add a dict for a new one (href, name, meta line, rent text, image, alt, blurb). Cards are generated from the list, so nothing else on the hub changes.
   - **A new space also needs its own page:** copy the `S101_*` / `s101_body` block (Suite 101) or the `S100_*` / `s100_body` block (Suite 100) and add it to the `PAGES` list in `build_site.py` (that list drives `sitemap.xml`, the Sitemap page and the 404 page's link grid).
2. Run the build with UTF-8 forced (see Gotchas): `set PYTHONUTF8=1` then `python tools/build_site.py`, then `python tools/audit.py`.
3. Deploy path: see "Deploying" below. Copy only the files you actually changed.

## Decisions (and who made them)

- **No dollar amounts anywhere.** Rent, deposits, cleaning fee and move-in totals were removed from the hub, Suite 100 and Suite 101 (pages, search descriptions, JSON-LD, sitemap text). Owner request: current tenants should not be able to look up rates, and rates change with the market. Pages say "Call for Pricing" / "Rates and move-in costs are available on request." The tenant-responsibility lines (gas/electric, internet/cable, quarterly maintenance fee/CAM, 2-year minimum, modified gross lease) were **kept on purpose** — owner explicitly said not to remove those.
- **Sizes:** Suite 100 = 528 sq ft (owner stated it; it is not in the brochures). Suite 101 = 956 sq ft (brochure floor plan).
- **"Lower level"** shown for both suites (hero line, lease-details row, hub card, descriptions). Suite 100's came from the folder/file names (`Lower Level\Suite100`); owner asked to add it to Suite 101 "like Suite 100".
- **Hub URL = `/2490/`.** Owner wanted something short and unambiguous because Centrale also leases residential properties (so not "/office-space-for-lease"), and easy to write down while driving. Went /office-space-for-lease -> /2490lease -> /2490. Old two addresses kept as redirects.
- **Branding:** Centrale Realty brand from `branding-kit` / the site (black `#0b0b0b`, gold `#baa383` / `#7d6849`, cream, Cormorant Garamond + Jost, C/R mark). The pages are generated with the site's own `page()` shell and the Grand Blanc `lst-*` listing classes, so they inherit header/footer/nav.
- **Wider content column (1100px)** on `/suite-100/`, `/suite-101/` and `/2490/` only, via a page-scoped inline `<style>` in `EXTRA_HEAD[...]` (`.prose{max-width:1100px}`). The rest of the site stays 800px. Owner wanted the videos to match the content width with no black letterbox bars.
- **Videos (Suite 101 only):** two walkthroughs, stacked full column width, 16:9, with the Centrale lockup burned into the upper-left, **no audio** (owner request), 1280x720 H.264 CRF 27, `+faststart`, with poster stills that also carry the logo.
- **Photos:** Suite 101's interior photos were replaced by the 8 photos from 2026-10-06. Exterior, building and floor plan for Suite 101, and all Suite 100 images, come from the brochure `.docx` files (clean originals, not the vignetted PDF renders). `20261006_143724.jpg` was not among the photos the owner attached, so it is unused; the January 2026 set is unused.
- **GitHub Pages copy removed.** The earlier React page at `vlrandaz-max.github.io/fantastic-octo-computing-machine/suite-101` (repo `fantastic-octo-computing-machine`, branch `claude/great-carson-0sfpwq`) was deleted at the owner's request. The sign work (`signs/`) still lives on that branch; copies are in `reference/sign/` here.
- **Sign:** 46.5" x 17.5", gold `#baa383` background, black text, text only, no QR code (owner request): FOR LEASE / 248-656-8830 / CENTRALEREALTY.COM/2490 with two full-width separator rules. Generated by `make_sign.py` (reportlab, Arial Black). The `-with-bleed` PDF is 46.75" x 17.75" with TrimBox 46.5 x 17.5 and 0.125" bleed. Phone number in the "Black" font is as large as the width allows (4.3" caps); a narrower Impact variant was tried and rejected (made FOR LEASE dwarf the phone number).

## Deploying (read before pushing anything)

- `centrale-realty-site` (GitHub, branch `main`) is the deployed copy. **Its `deploy.yml` uploads to the web host over FTPS automatically on every push to `main`** when the FTP secrets are set (they are). Only push there when you mean to publish. It uploads only files whose size changed (so an edit that keeps a file exactly the same byte-size is skipped; tick "force") and never deletes.
- This branch's `deploy-sftp.yml` (Network Solutions) is manual-only. `deploy-pages.yml` only runs for `claude/great-carson-0sfpwq`. Pushing to `claude/determined-bardeen-xoc8n8` does not deploy.
- How the office-space files were published: edit `tools/build_site.py`, build, copy only the changed `site/` files into a clone of `centrale-realty-site`, replace the stylesheet cache-buster in the copied HTML with the live one (`styles.css?v=a746023f`), commit, push.
